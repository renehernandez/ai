# Retrospective and Solution Note

Use this shape only after Explore establishes a reusable reader outcome.

```text
Problem and context:
Non-obvious mechanism or constraint:
Evidence from the completed work:
Reusable decision or diagnostic pattern:
Where the pattern does not apply:
How future work verifies it:
```

Prefer a focused note over a task narrative. Omit facts obvious from the final
code, generic lessons, personal workflow telemetry, and speculative policy.
Follow the repository's existing location and naming convention. A rule, skill,
automation, memory, or provider update is a separate accepted outcome, never an
automatic consequence of the retrospective.
